# UI 语言迁移单

这是一份在“把本项目交给 Codex”之前填写的短决策单。它把多个 UI
参考项目变成一份**有主次、有证据、有原创边界的目标设计说明**。

不要把这份文件写成页面清单。它要回答的是：

> 目标产品为什么借用某条设计原则？它要怎样改写？如何证明改写后仍然好用？

## 1. 目标产品

```text
产品名称：
主要用户：
产品的一个核心任务：
平台：web / desktop / mobile / cross-platform
当前不做：
```

## 2. 参考项目职责

只允许一个主设计语言；其他项目只能贡献明确命名的维度。

| 角色 | 项目 | 贡献维度 | 不贡献什么 |
|---|---|---|---|
| 主设计语言 | 本项目 / 其他项目 | shell、密度、状态、排版…… | 不复制路由、品牌、数据 |
| 次级维度 | 参考项目 B | 媒体卡片 / 图表 / 动效…… | 不带入它的整套颜色和布局 |
| 次级维度 | 参考项目 C | …… | …… |

冲突优先级：

```text
产品任务 > 平台可用性与无障碍 > 主设计语言 > 次级维度 > 装饰
```

## 3. 借用维度的证据表

每一行都必须能回到参考项目的文档或 Demo 区域。

| 借用维度 | 来源文件或 Demo 区域 | 抽象原则 | 目标产品的原创改写 | 明确不复制 |
|---|---|---|---|---|
| shell | 例如 `DEMO-MAP` 的导航和顶栏 | 按用户意图组织全局入口 | 目标产品自己的任务分组 | 原菜单名、原品牌 |
| 状态表达 | 例如队列和设置区域 | 状态要带原因和下一步 | 使用目标产品自己的状态模型 | 原业务状态名 |
|  |  |  |  |  |

## 4. 目标页面职责

每个页面只写一个主任务。没有对应用户决定的模块，不因为参考 Demo
里出现过就添加。

| 页面 | 用户来这里做什么 | 首屏结论 | 主动作 | 支撑证据 | 不放什么 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

## 5. 状态和恢复路径

只填写目标产品真实存在的状态；不要为了“看起来完整”虚构状态。

| 数据区域或操作 | 正常 | loading | empty | stale/offline | error/retry | 成功后的可见结果 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

## 6. 响应式改写

```text
桌面端的主要阅读顺序：
平板端首先减少什么：
移动端保留的首要任务和动作：
移动端变成抽屉 / 单列 / 横向滚动的内容：
浮动入口如何避让内容和安全区域：
```

## 7. 原创边界

```text
原创品牌和产品名称：
原创路由和页面职责：
原创业务实体、文案和演示数据：
没有复制的截图、Logo、海报、源码或私有行为：
```

## 8. 验收证据

- [ ] 首屏能看出页面职责和信息优先级。
- [ ] 至少一个关键操作有完整的进行中、成功和失败/恢复反馈。
- [ ] 至少检查一个次级页面和一个窄屏宽度。
- [ ] 颜色、间距、圆角和动效没有脱离主设计语言另起一套。
- [ ] 页面没有因为参考 Demo 存在某个模块就机械增加模块。
- [ ] 使用 `docs/UI-REVIEW-CHECKLIST.zh-CN.md` 完成一次人工验收。
