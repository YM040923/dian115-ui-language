# UI 设计验收清单

这份清单用于判断一个新页面是否真正使用了本项目的设计语言，而不是只换了颜色和圆角。

## 1. 产品与页面职责

- [ ] 页面只有一个主任务。
- [ ] 页面标题能说清“当前在哪里”。
- [ ] 说明文字能说清“这个页面为什么存在”。
- [ ] 支撑模块不会抢走主任务的注意力。
- [ ] 没有因为参考页面有某个模块，就机械地增加同类模块。

## 2. 信息层级

- [ ] 首屏先给结论，再给证据，再给操作。
- [ ] 最重要的数值、状态或动作有明确的视觉优先级。
- [ ] 指标带有来源、时间范围、单位或含义。
- [ ] 长任务同时显示状态、进度、时间/来源和下一步动作。
- [ ] 详情页没有把所有内容都做成同样大小的卡片。

## 3. 视觉系统

- [ ] 颜色来自语义角色，而不是每个模块自创颜色。
- [ ] 成功、警告、失败都带文字或图标，不只依靠颜色。
- [ ] 间距大部分来自统一的 spacing scale。
- [ ] 圆角、边框和阴影有层级关系。
- [ ] 页面背景、工作面、信息行能被区分。
- [ ] 深色模式不是简单反色，仍然保持层级和对比度。

## 4. 交互反馈

- [ ] 刷新有进行中、完成和失败反馈。
- [ ] 保存有 dirty、saving、saved 和 validation failure 状态。
- [ ] 外部连接有测试中、可用、不可用和重试路径。
- [ ] 队列项目有运行中、排队、完成、失败、取消等区别。
- [ ] 搜索和筛选能显示当前条件、结果数量或空状态。
- [ ] Toast 只用于短暂确认，重要结果不会只停留在 Toast 中。

## 5. 响应式

- [ ] 1024px 以上仍保持清晰的主任务与支撑任务关系。
- [ ] 768px 左右会先减少列数，而不是压缩文字到不可读。
- [ ] 移动端是有意识的单列顺序，而不是桌面布局溢出。
- [ ] 主动作、标题和关键状态在移动端仍然容易触达。
- [ ] 浮动入口不会遮挡内容、底部提示或系统边缘。
- [ ] 长表格、长筛选和长名称有明确的移动端处理方式。

## 6. 可访问性

- [ ] 键盘可以到达所有关键控件。
- [ ] 焦点状态清晰可见。
- [ ] 抽屉和对话框有标题、关闭路径、Escape 行为和焦点回归。
- [ ] 图表有文本摘要或可读数据。
- [ ] 进度指示器暴露任务名称和当前值。
- [ ] 200% 文字缩放不会隐藏关键操作。
- [ ] `prefers-reduced-motion` 下仍然可用。

## 7. 原创边界

- [ ] 产品名称、品牌、路由、业务实体和数据模型是原创的。
- [ ] 没有复制参考站点的截图、Logo、海报或私有实现。
- [ ] 借用的是原则和模式，而不是页面截图和逐像素位置。
- [ ] 如果组合多个参考，已经写明每个参考贡献的维度。

## 最低验收标准

一个页面至少要通过：

1. 一次宽屏视觉检查。
2. 一次窄屏视觉检查。
3. 一条关键交互路径。
4. 一个非成功状态。
5. 一次键盘或可访问性检查。
6. 一次“是否误复制参考产品”的人工检查。
